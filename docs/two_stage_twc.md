# Two-stage TWC and VQA

Run `notebooks/twc_colab.ipynb` top to bottom. Set a new `RUN_ID` for a new experiment; keep it unchanged after a disconnect to resume the same two independent Hub runs. The notebook requires a Hub token before training. `configs/pretrain.yaml` and `configs/twc_vqa.yaml` hold the stage settings. Each epoch saves a full resumable checkpoint and the final model is uploaded to its stage's repository.

Pretraining reads and prepares only the train annotation split and never evaluates validation or test. A shared image or OCR archive can contain files for other splits; it may be downloaded/extracted as a data asset, but only train samples are loaded. The correction lexicon uses the external term list and dictionary, not training questions or answers. The pretrain collator does not tokenize questions or answers and seeds augmentation from image identity. It preserves every train row. ViT5 contains only its encoder and shared embeddings; image and full original and related OCR streams enter the encoder in that order. CLIP uses the same no-question adapter mode in both stages. Related OCR uses p=0.35.

`paper_bce` implements row-wise softmax of cosine similarity divided by fixed tau=0.07 followed by symmetric binary cross-entropy on the original/related soft targets, ignoring padded and masked cells. It does not renormalize targets. This differs from the historical `bce` mode (independent sigmoid BCE) and `infonce` (softmax cross-entropy), which remain available for legacy runs. Fixed tau is a deliberate departure from learnable-temperature runs.

VQA constructs a full ViT5 with its pretrained decoder, then copies the complete shared encoder, CLIP and OCR state from the pretrain checkpoint; key mismatches fail explicitly. The shared embedding remains tied to decoder and output embeddings. Its metadata records the pretrain source. This is a weight initialization, not an optimizer/global-step resume: later VQA checkpoints resume only their own stage. The downstream model has no TWC parameters or targets, uses VQA loss alone and p=0.7, and concatenates `[image, original OCR, related OCR, question]`. Legacy configs lacking `input_order` retain question-first behavior. Both configs start from LR 1e-4, batch size 32, and five epochs.
